# Security audit — leeftoken/Leef-signer

Official site: https://leeftoken.io. Official GitHub: https://github.com/leeftoken/Leef-signer. Upstream fork: https://github.com/NostrDanish/0xsigner (not moved).

## Status on 24 Oct 2026 (Europe/Copenhagen)

The 21 Oct report said `providers.js` was syntactically invalid and that `nip98` auth returned true. Both are closed on this branch.

| ID | Was | Now |
|----|-----|-----|
| LS-6 | HIGH. Orphaned top-level `return` in `providers.js` made every generated worker invalid, and nothing parsed the `?raw` sources. | Fixed earlier on main. `npm run test:syntax` parses `core.js`, `providers.js`, `entry.js` and the assembled worker. `.github/workflows/ci.yml` runs that check on push and pull request. Pages deploy runs it before `npm run build`, and installs with `npm ci`. |
| LS-1 | HIGH. `checkPublicAuth` returned true for `publicAuth: "nip98"` with no NIP-98 check. | Fail closed. `nip98` returns false. The wizard only offers None and API key, so a new deploy cannot select it. A saved manifest that still says `nip98` rejects callers. |

## Still open

| ID | Severity | Issue |
|----|----------|-------|
| LS-2 | MEDIUM | `publicAuth: "none"` is an unauthenticated public spend of the upstream key. Rate limits are per isolate. CORS does not stop non-browser clients. `/api/judge` adds a second paid route. |
| LS-3 | MEDIUM | nsec login can be stored in `localStorage` on the same origin that handles the Cloudflare API token during deploy. |
| LS-4 | LOW | GitHub secret scanning / push protection was not enabled on 21 Oct. No root `SECURITY.md`. |
| LS-5 | LOW | The Cloudflare API token is typed in the browser for deploy. Confirm it stays memory-only and is dropped on unload. |

## Secrets

Provider secrets are read from Worker env only. The client cannot override the model. Upstream errors stay opaque. Authorization and Cookie are not forwarded on generic REST. No keys were found in the tree.

## Do not reopen

Do not treat the 21 Oct "main is broken" sentence in `IMPROVE-2026-10-21.md` as current. That file's top status line says the syntax fault is fixed.
