# Security Audit — NostrDanish/Leef-signer — 2026-10-21

## Summary
Re-audit (delta from 2026-10-20). Two commits landed on main since the last audit: a model-choice/timeout fix (6802ebce, pre-dates the prior audit's HEAD) and the new TypeSafe (Jev) provider (4d43cc0, 2026-10-20 07:56Z, NEW). The TypeSafe adapter itself is well-built (server-fixed model, strict typed-question validation with size caps, secrets from env only, opaque errors). **However, that commit left `src/lib/signer/runtime/providers.js` syntactically invalid**: an orphaned duplicate of the body-read tail was pasted at module top level (lines ~476–502) — `node --check` fails (ESM: "Illegal return statement"; the block also re-declares `text`/`data` and ends with an extra `}`). Because `generator.ts` inlines `providers.js` verbatim (`?raw`) into every generated Cloudflare Worker, **any worker generated/deployed from the current UI is broken JavaScript** (the dashboard itself still builds since the raw import isn't parsed). The previously-flagged nip98 auth trap is unchanged. Findings: 0 CRITICAL / 2 HIGH / 2 MEDIUM / 2 LOW.

Reviewed: full regenerated runtime (`core.js`, `entry.js`, `providers.js` — fetched raw and syntax-checked), `generator.ts` import mechanism. All provider secrets (TYPESAFE_API_KEY, OPENAI/PPQ, Brave, Tor token, etc.) are read from Worker env only; client `model` override is rejected; upstream errors mapped to opaque messages; Authorization/Cookie never forwarded (generic-rest NEVER_FORWARD set intact). **No secrets committed.** GHAS secret scanning still unavailable — manual review was the check.
