# Security Audit — NostrDanish/Leef-signer — 2026-10-20

## Summary
TypeScript/React dashboard (fork of NostrDanish/0xsigner) that generates and deploys a Cloudflare Worker AI/API gateway (OpenAI-compatible proxy to PPQ/OpenAI/Brave etc.). Secret handling design is strong: secret VALUES are entered in the browser, pushed directly to Worker Secrets via the Cloudflare API, and never stored in the manifest, repo, or generated code; generated runtime has an SSRF guard (fixed upstream hosts), CORS reflection only for allowlisted origins, opaque error bodies, per-isolate rate limiting, and header-forwarding that excludes `Authorization`/`Cookie`. Findings: 0 CRITICAL / 1 HIGH / 2 MEDIUM / 2 LOW.

## Findings
| ID | Severity | File/Area | Issue | Recommended fix |
|----|----------|-----------|-------|-----------------|
| LS-1 | HIGH | src/lib/signer/runtime/core.js + providers.js | `publicAuth: "nip98"` is a no-op: `checkPublicAuth()` returns `true` for nip98 ("structural NIP-98 check is per-route") but no route in providers.js/entry.js performs any NIP-98 signature verification. An operator who selects nip98 gets an **unauthenticated gateway while believing it is authenticated**. Not exploitable in the default LEEF preset (publicAuth `none`, honest), but the option is a trap. | Implement real NIP-98 verification (verify event signature, kind 27235, URL + method tags, fresh `created_at`) per route, or remove/disable the nip98 option from the UI until implemented. |
| LS-2 | MEDIUM | runtime/core.js (publicAuth "none" + CORS) | With publicAuth `none`, the gateway is unauthenticated; CORS only restricts browsers — any curl/bot can call `/api/ai` and spend the owner's paid upstream quota (PPQ/OpenAI/Brave). Mitigations present: per-IP 20 req/min (per-isolate, best-effort, documented), /api/health rate-limited, CORS allowlist blocks browser abuse. | Offer/require a shared bearer token option for public gateways; document that "none" = public spend endpoint; consider Cloudflare-rate-limiting rules (edge, persistent) instead of per-isolate. |
| LS-3 | MEDIUM | src/hooks/useLoginActions.ts (Nostr login) | nsec login is supported and @nostrify/react persists logins (private key material) to localStorage — an XSS in the dashboard would expose the operator's Nostr key on the very UI that holds CF API tokens during deploy sessions. | Prefer NIP-07 extension / bunker-only login for this admin tool; if nsec login stays, warn and avoid persistence (session-only). |
| LS-4 | LOW | Repo settings | GHAS secret scanning not enabled; no SECURITY.md. | Enable secret scanning + push protection; add SECURITY.md. |
| LS-5 | LOW | cloudflare.ts flow | CF API token is entered in-browser for deploys (transient use observed; no repo persistence found). Verify it is never written to localStorage and is discarded after deploy. | Confirm token is memory-only; add explicit "forgotten on unload" note in UI. |

## Secrets Check
Reviewed: `src/lib/signer/{manifest.ts, cloudflare.ts, templates.ts}` and full generated-worker runtime (`runtime/{core.js, entry.js, providers.js, generator.ts}`), hooks (incl. `useLoginActions.ts`), README, package.json, .gitignore; code searches for `nsec1`, `sk-`, nip98 patterns (0 hits; note GitHub code search reported `incomplete_results`, manual review was primary). **No secrets committed.** Manifest schema explicitly excludes secret values (values go to Worker Secrets only); generator embeds only non-secret config. .gitignore covers dist/.deploy-tmp (deploy temp dir with creds is ignored — good).

## Dependency Notes
Modern React/Vite + @nostrify/nostr-tools stack; esbuild-wasm used in-browser to transpile the generated worker before upload (regression-tested). No git-URL deps observed. Keep lockfile committed and run npm audit in CI.

## Code Red-Flag Review
- Generated worker: SSRF-guarded fixed upstream hosts, path allowlists per provider, no open proxy (generic provider fixes endpoint in manifest; `forwardHeaders` never includes Authorization/Cookie), CORS only reflects allowlisted origins (default []), opaque 4xx/5xx bodies, upstream timeouts mapped to 504.
- No eval of remote input; worker source is generated from local templates and transpiled client-side.
- Auth: see LS-1/LS-2 — the one real gap.

## Fork/Upstream Freshness
Fork of NostrDanish/0xsigner. Leef-signer HEAD 2026-10-20 (model-choice optimization + timeout race fix) is **~1 month AHEAD** of upstream HEAD 2026-09-22 (worker TS→JS transpile fix). Not stale; upstream has no newer security-relevant commits. No action needed.

## Recommended Actions
1. Implement or remove the nip98 publicAuth option (LS-1).
2. Add bearer-token auth option for public gateways; move rate limiting to Cloudflare edge rules (LS-2).
3. Restrict Nostr login to extension/bunker for this dashboard (LS-3).
4. Enable GHAS secret scanning; add SECURITY.md (LS-4).
5. Confirm CF token is memory-only (LS-5).
