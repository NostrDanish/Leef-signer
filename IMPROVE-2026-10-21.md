# Improvement Deep-Dive — Leef-signer — 2026-10-21

Scope: `main` (Universal Edge Signer / 0xSigner fork — Cloudflare Worker gateway generator,
`src/lib/signer/runtime/{core,providers,entry}.js` + `generator.ts`). **main is currently
broken**; this report pinpoints the fault and the gates that would have caught it.
Dep versions verified against the npm registry this session.

## Top recommendations (ranked, with effort S/M/L)

1. **Fix the broken `providers.js` on main (S).** Immediately after `typesafeHandle`'s
   closing brace there is a **duplicated, orphaned copy of `openaiHandle`'s body-read tail**
   (the "abort signal bounds the whole request INCLUDING the body read" comment + `let text`
   / `let data` block, ending in `return … }`). That stray block contains a top-level
   `return` statement → **SyntaxError: the entire module cannot parse**. Since the generator
   imports these files via `?raw` (string), neither `tsc --noEmit` nor `vite build` ever
   parses them — which is exactly how a broken main shipped green. Delete the duplicated
   block (it is verbatim-dead code; `typesafeHandle` above it is complete and correct).
2. **Add a syntax-gate CI job (S).** `node --check src/lib/signer/runtime/*.js` on every
   push/PR — 2 lines, would have caught this instantly. There is **no CI at all** today,
   only `deploy.yml`.
3. **Port upstream 0xsigner's `generator.test.ts` (S–M).** Beyond parsing the inputs, the
   round-trip test should `buildWorkerSource()` for a sample manifest and `node --check`
   (or `new Function` / vm-parse) the **generated output** — that catches import/export
   stripping regressions in `generator.ts` itself, which `?raw` imports make invisible to
   the toolchain.
4. **Implement or remove NIP-98 `publicAuth` (M).** `core.js checkPublicAuth()` returns
   `true` unconditionally for `{type:'nip98'}` ("presence-only here; structural check is
   per-route") — but **no per-route structural check exists anywhere in `entry.js`**.
   Net effect: a deployment configured with NIP-98 auth is wide open while believing it is
   authenticated. Either implement real NIP-98 verification (kind 27235 event in the
   `Authorization: Nostr <b64>` header; check `u` + `method` tags, `created_at` within
   ±60 s, Schnorr signature — `nostr-tools` is already a dependency) or remove the option
   from the wizard/manifest schema until it ships. Do not leave the no-op.
5. **`deploy.yml`: `npm install` → `npm ci` (S)** and run the new gate job **before** the
   Pages deploy so a broken runtime can never be published again.

## Missing gates (CI/tests/protection)

- **No CI workflow** — `.github/workflows/` contains only `deploy.yml` (Pages). Nothing runs
  `tsc`, eslint, or vitest on push/PR despite `package.json` having a `test` script that
  does all three. Add `ci.yml` mirroring leef-trader's (npm ci → typecheck → lint → vitest →
  build) **plus the `node --check runtime/*.js` gate** (S).
- **No tests in the repo** (`src/` has a 148-byte `App.test.tsx` placeholder; nothing covers
  `generator.ts`, `manifest.ts`, or the runtime). The `?raw`-import architecture makes the
  generator the highest-value test target — port upstream's generator test (S–M).
- **`deploy.yml` uses `npm install`** (unpinned, can silently pull new transitive deps) →
  `npm ci`; and make the deploy job depend on the gate (S).
- **No branch protection** on `main` (`protected: false`) — require CI green before merge (S).
- **No gitleaks** — the whole point of this repo is secrets handling; add
  `gitleaks/gitleaks-action@v2` (S).

## Quick wins (code/config)

- **`package.json` name is `"mkstack"`** (Shakespeare template leftover) → `leef-signer`;
  add a real `description` (S).
- **`build`/`test`/`dev` scripts run `npm i --silent` inline** — mutation as a side effect
  of building; remove it and let CI own install (S).
- **Per-isolate rate limiting:** `core.js`'s `buckets` Map resets per Worker isolate, so the
  documented 429 semantics are best-effort. Cloudflare now offers a first-party Workers
  Rate Limiting binding — adopt it (config-only) or note the limitation honestly in the
  wizard UI copy (S).
- **Stale comment:** the `checkPublicAuth` nip98 comment claims a per-route check that does
  not exist — comments asserting security properties must be true or deleted (S, folded
  into the NIP-98 fix).

## Ecosystem alignment notes

- **Nostr:** the only NIP surface is NIP-98 (HTTP auth) in the manifest's `publicAuth`.
  Current NIP-98 expectations: kind 27235, `u` tag exact-match, `method` tag, freshness
  window, and `Authorization: Nostr <base64-event>`. Implementing it here also gives
  leef-trader's `/api/jev` owner-gating a reusable reference implementation.
- **Cloudflare Workers:** `generator.ts` targets `compatibility_date: 2026-08-01` — fine;
  keep it bumpable per deployment. Runtime uses only standard Worker APIs (good). The
  README's "429 + Retry-After" claim should note per-isolate semantics until the Rate
  Limiting binding lands.
